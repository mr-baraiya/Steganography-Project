Under The Hood

Header Binary Protocol Specification

CELATUS injects a 10-byte binary validation header prior to bitwise LSB injection to enforce checksum key verification.

10-Byte Header Byte Layout:

The payload bitstream is preceded by 80 bits (10 bytes) of structured metadata:

Bytes 0??3: Signature
0x43 0x45 0x4C 0x41 ('CELA')
Bytes 4–5: Key Checksum
16-bit Passcode Hash
Bytes 6–9: Payload Size
32-bit Integer Length
Bytes 10+: Encrypted Payload

Got Questions?

Frequently Asked Questions

How does CELATUS conceal secret text inside images?
CELATUS uses Least Significant Bit (LSB) channel steganography. It replaces the least significant bit of RGB pixel values in your carrier image with payload bits. Because pixel values change by at most 1 unit, the human eye cannot perceive any difference.
Is my data safe or uploaded to any server?
CELATUS operates 100% offline. All pixel manipulation and passcode hashing occur locally on your machine or phone. No network calls or cloud telemetry exist.
What happens if someone enters an incorrect passcode key?
CELATUS evaluates the 16-bit passcode key checksum in the binary header. If an incorrect passcode is supplied, CELATUS denies access and aborts payload extraction.
